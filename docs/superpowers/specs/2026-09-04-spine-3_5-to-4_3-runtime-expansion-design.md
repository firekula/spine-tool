# Spine 3.5–4.3 多 Runtime 扩展设计

## 1. 目标

在现有纯浏览器 Spine 预览与 Atlas 子图导出工具中，将骨骼预览支持范围从 3.8、4.0、4.1、4.2 扩展到以下八条版本线：

- Spine 3.5
- Spine 3.6
- Spine 3.7
- Spine 3.8
- Spine 4.0
- Spine 4.1
- Spine 4.2
- Spine 4.3

这里的“全版本”定义为：JSON 声明的版本只要属于上述 `major.minor`，所有稳定补丁号都路由到同一版本线的固定 Runtime；SKEL 支持范围为 3.8–4.3。3.5–3.7 的官方 Web Runtime 没有二进制读取器，因此这些版本只支持 JSON，SKEL 会得到明确的中文能力错误且不会交给其他 Runtime。带 `-beta` 等后缀的导出也按 `major.minor` 路由，但界面必须提示其兼容性不受官方稳定版承诺保证。

网站版、离线版和源码版继续保持同样功能。所有 Spine 文件仍只在浏览器本地处理。

## 2. 已确认的问题

用户提供的 `xhm.json` 明确声明 `spine: "3.8.75"`。现有版本检测器能够正确将其识别为 Spine 3.8，失败发生在官方 3.8 Runtime 的数据解析器中：该 Runtime 对恰好 `3.8.75` 写有显式拒绝条件，并抛出“请使用更新版本重新导出”的错误。

在不修改原文件、仅在内存诊断中绕过该版本判断后，样本能够读出 19 根骨骼、6 个插槽、1 个皮肤和 1 个动画。这证明当前样本的主要阻断点是 Runtime 的主动拒绝，而不是文件配对、Atlas 解析或普通版本白名单。

官方仍将 3.8.75 视为存在已知导出问题的特殊版本，因此工具对它提供“尽力兼容”，不能把它描述成官方保证兼容。

## 3. 方案选择

采用八套隔离 Runtime，而不是使用一个新 Runtime 读取所有旧数据，也不在导入时把旧数据转换为 4.3。

原因：Spine 官方兼容边界是 `major.minor`。同一版本线内的稳定补丁版本兼容，跨版本线的数据格式可能改变，尤其 SKEL 不适合在浏览器中做未经官方保证的通用转换。

替代方案及不采用原因：

- 单一 4.3 Runtime：包较小，但不能可靠读取 3.5–4.2 JSON 或 3.8–4.2 SKEL，也不能补足 3.5–3.7 官方 Web Runtime 缺失的二进制能力。
- 旧数据先转换到 4.3：需要维护多个数据转换器，SKEL 风险高，并改变了“预览原始导出”的产品边界。
- 旧版本仅允许 Atlas 导出：实现简单，但不满足动画、皮肤和插槽预览需求。

## 4. 版本识别与选择

### 4.1 JSON

从 `skeleton.spine` 读取原始版本字符串，提取前两个数字段。例如：

| 原始版本 | Runtime 版本线 | 状态 |
| --- | --- | --- |
| `3.5.51` | 3.5 | 自动支持 |
| `3.8.75` | 3.8 | 自动支持，显示特殊警告 |
| `3.8.99` | 3.8 | 自动支持 |
| `4.3.9` | 4.3 | 自动支持 |
| `4.3.0-beta` | 4.3 | 尝试加载，显示 Beta 警告 |
| `4.4.0` | 无 | 不自动加载，允许手动选择 |

### 4.2 SKEL

版本检测器继续只读取受限长度的二进制头，不解析完整文件。它覆盖 3.5–3.8 的旧字符串头和 4.x 的新头布局；识别 3.5–3.7 SKEL 只用于给出精确能力错误，不会启动预览。只有头部检测失败时才进行受限 ASCII 回退扫描。

若 SKEL 无法确定版本，用户可以从八条版本线中手动选择。手动选择只决定尝试使用哪个 Runtime，不改变文件内容，也不把成功描述为自动识别；手动选择 3.5–3.7 仍会返回 SKEL 能力错误。

### 4.3 界面状态

导入后同时显示：

- 素材原始版本，例如 `3.8.75`；
- 选择的 Runtime 版本线，例如 `3.8`；
- 选择来源：自动识别或用户手动选择；
- 特殊兼容提示，例如 3.8.75 或 Beta 数据。

不允许在识别到受支持版本后静默换用另一条 Runtime。

## 5. Runtime 注册表与隔离

将当前硬编码加载表扩展为强类型 Runtime 注册表。每个条目包含：

- `majorMinor`；
- 懒加载函数；
- 官方来源、固定版本或提交、完整 SHA-256；
- Atlas 构造方式；
- Skeleton JSON 读取器，以及版本支持时的 Binary 读取器；
- 世界变换、皮肤组合、插槽控制和渲染所需的版本适配函数；
- 纹理 Alpha 策略；
- 特殊兼容补丁标记。

每条 Runtime 单独生成动态 chunk，不共享其 Spine Core 类型。应用层只依赖现有统一 bridge 接口，从而避免 `instanceof`、静态单例和枚举值在不同 Runtime 之间串线。

3.5–3.8 优先从官方 `spine-runtimes` 对应稳定分支或标签构建，固定到明确提交并保留来源记录。4.0–4.3 使用可获得的官方 `@esotericsoftware/spine-webgl` 稳定包并锁定完整版本。若某条旧版本线的 Web Runtime 目录结构不同，只在该版本的 adapter 内适配，不把差异泄漏到工作区组件。

## 6. Spine 3.8.75 特殊兼容

### 6.1 行为

对原始版本恰好为 `3.8.75` 的 JSON 和 SKEL：

1. 自动识别为 3.8；
2. 显示黄色警告，说明官方认为该版本存在已知导出问题；
3. 使用带有受控兼容补丁的 3.8 Runtime 尝试读取；
4. 不修改用户上传的文件，不导出被篡改的骨骼数据；
5. 若解析或渲染失败，保留具体错误，并继续允许 Atlas-only 子图导出。

### 6.2 补丁边界

兼容补丁只移除官方 Runtime 对版本字符串 `3.8.75` 的主动拒绝，不重写骨骼、动画、网格、约束或附件数据。补丁以可审查差异和来源哈希记录，避免用通用字符串替换绕过其他格式检查。

页面不得声称所有 3.8.75 文件都一定能正确播放。导出报告只记录 Atlas 子图恢复结果，不把骨骼兼容加载结果当作图像倍率证据，除非 Runtime 确实成功读出对应附件元数据。

## 7. 3.x Alpha 模式

旧版 Atlas 可能不包含可靠的 `pma` 字段。现有 3.8 的显式 PMA/Straight 选择扩展到需要它的 3.5、3.6、3.7、3.8 Runtime：

- 文件名只能预选默认值；
- 用户必须确认后才启动预览；
- 选择值传入对应 Runtime bridge；
- 4.x 继续优先遵循 Atlas 页级 `pma`；
- Atlas 子图导出继续输出普通 straight-alpha PNG。若源纹理为 PMA，导出层必须保持现有明确约定和测试，不把预览混合模式误用于裁图坐标逻辑。

## 8. Atlas、倍率与 ZIP

现有 Atlas-only 导出路径保持独立，不因新增 Runtime 而改写：

- 旧版 `xy/size/orig/offset/rotate` 与新版 `bounds/offsets` 继续归一化；
- 单页和多页 PNG 继续按规范化页名匹配；
- Atlas 页级 `scale` 仍是直接倍率证据；
- Runtime 附件尺寸仅作为补充证据；
- 多页倍率冲突仍要求用户确认；
- ZIP 路径继续遵守 Windows 可移植限制。

新增旧 Runtime 只能增加附件倍率样本，不能降低 Atlas 直接证据优先级，也不能让预览失败阻断有效 Atlas 的导出。

## 9. 错误与降级

错误处理按以下层次区分：

1. 文件组成错误：缺少 Atlas、骨骼或 Atlas 声明的 PNG，阻断导入。
2. 版本检测失败：保留 Atlas 资源，显示八版本手动选择器。
3. Runtime 不匹配或解析失败：说明素材原始版本、尝试的 Runtime 和原始错误；允许重新选择 Runtime。
4. 3.8.75 特殊失败：说明该版本的官方已知问题，并建议能取得工程文件时使用其他 3.8 补丁重新导出；Atlas 导出继续可用。
5. WebGL 或渲染失败：降级到 Atlas-only，不释放导出所需纹理。

所有提示保持中文，并给出可执行的下一步。

## 10. 测试与验收

### 10.1 版本检测

- JSON 覆盖八条版本线、不同补丁号、Beta 后缀、未知版本和损坏 JSON；
- SKEL 头检测覆盖八条版本线、截断头、未知布局和受限 ASCII 回退；3.5–3.7 识别后验证能力错误，3.8–4.3 验证真实加载；
- `3.8.75` 必须自动识别成 3.8，而不是落入手动选择器。

### 10.2 Runtime

每条版本线至少使用一套来自官方仓库的 JSON fixture；3.8–4.3 另使用真实 SKEL fixture，3.5–3.7 则验证明确拒绝 SKEL 且不跨版本回退。对可加载的格式验证：

- 正确动态 chunk 被加载；
- 骨骼数据实际解析；
- 动画、皮肤、插槽和 Region 附件元数据可读取；
- 至少绘制一个非透明 WebGL 像素；
- 资源释放后对象 URL、纹理和 WebGL 资源不泄漏。

用户提供的 `xhm` 三件套用于本地验收 3.8.75 兼容路径，但未经额外授权不复制到公开源码、网站或离线包。仓库内另建最小化的合成 3.8.75 回归 fixture，用于证明主动拒绝被受控绕过。

### 10.3 端到端

- 自动识别八条 JSON 版本线并进入正确预览，3.8–4.3 SKEL 进入对应预览；
- 3.5–3.7 SKEL 显示中文能力错误，且不交给其他 Runtime；
- 手动选择器列出八条版本线；
- 3.x Alpha 确认流程正确；
- 3.8.75 显示警告并尽力加载；
- Runtime 失败后仍可导出 Atlas ZIP；
- 现有旋转、裁剪、倍率、路径安全、离线无外部请求测试全部保留。

### 10.4 来源与离线安全

- 每个 Runtime 的来源文件、许可证、版本或提交及 SHA-256 可重复验证；
- 在线构建和离线构建都包含八个隔离 Runtime chunk；
- 离线审计只允许精确路径与精确 SHA-256 命中的已审查 Runtime；
- 任意 Runtime 字节变化都必须使打包 fail-closed；
- 离线 ZIP 连续生成两次应得到相同 SHA-256。

## 11. 交付

完成后重新生成并交付：

- 更新后的私有静态网站；
- 更新后的离线 ZIP；
- 更新后的完整源码 ZIP。

README 更新支持矩阵、3.8.75 风险说明、3.x Alpha 选择和手动 Runtime 选择方法。

## 12. 限制与非目标

- 不承诺 Beta 导出与稳定 Runtime 完全兼容，只提供明确标记的尽力加载。
- 不承诺官方已知有问题的所有 3.8.75 数据都能正确播放。
- 不把旧 JSON/SKEL 转换或保存为新版格式；3.5–3.7 SKEL 不在预览支持范围内。
- 不修改用户原始文件。
- 不恢复缩小导出前已经丢失的真实像素细节。
- 无法为历史上每一个补丁版本取得并分发一套独立 fixture；验收保证版本路由、对应官方 Runtime 和代表性真实格式覆盖，而不是逐个补丁号进行穷举认证。
